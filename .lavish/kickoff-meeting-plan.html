Before the meeting — you, ~40 minutes

Pre-flight checklist

1 · Publish the specs

Commit and push gdd-planning/, then rewrite the file:/// links to repo-relative paths so they work for everyone.

2 · Land the Strapi helper

Merge #9 first (it has the env + router plumbing), then rebase #8 and #11 onto it. Close #1–#6 — six months stale, superseded.

3 · Land the Shadcn baseline

Init Shadcn and commit the shared primitives (card, badge, tabs, dialog, input, select, sheet, slider, form, progress) so nobody re-inits.

4 · Smoke-test clean clone

Fresh clone → npm i → npm run dev. If that fails for you, it fails for all six and the hour is gone.

Fallback if #3 doesn't land: Tell students to build with plain Tailwind and swap in Shadcn later. Do not let six people idle waiting on a dependency install.
The hour

60-minute run sheet

Weighted deliberately: 28 of 60 minutes are hands-on-keyboard. Talking is capped at 22 minutes because the outcome you asked for is code, not consensus.

0–5

Where the project actually stands

Blunt and short: master has been quiet since April, ten PRs went unreviewed, and that stops today. Name the reset without assigning blame — most of them wrote that code as coursework months ago.

5–12

Tour of the foundation you landed this morning

Screen-share master and show the four things they each need:

  • Where their spec lives, now that it is pushed
  • frontend/src/api/strapi.ts — the helper, and how to call it
  • frontend/src/components/ui/ — the Shadcn primitives, already installed
  • .env.example → .env, and npm run dev working
12–22

Module handoff — 6 × 100 seconds

One pass around the room. Each student states back: my module, my route, my first commit. You are listening for misunderstanding, not delivering a briefing — the cards below do that. Hold the timer. This is the section that historically eats the hour.

22–50

Live build block — the point of the meeting

Everyone codes in the room, together, for 28 minutes. You float and unblock — you do not present. Laptops open, branch created, first file written.

This is the highest-value part of the hour: the friction that kills student momentum (env vars, install failures, "where does this file go") surfaces while you are standing right there.

50–57

Push & open draft PRs — round robin

Everyone pushes and opens a draft PR before standing up. Drafts signal "in progress" and keep your review queue honest. Confirm six PR links land in the channel — that is your proof the meeting worked.

57–60

Close: what happens before next session

State your review turnaround out loud and commit to it. The backlog grew because review never came — a promise here is what prevents a repeat.

Before you run this

Open questions I couldn't resolve from the repo

Who are these six people?

The kickoff doc names Cyncia Chen and Ediale Odia. GitHub shows MeiyanChen25 and Galboinkus, plus documentation_mohamed and documentation_dennis branches. Either the doc is stale or the roster changed — fix this before you assign modules on a slide.

The sprint plan contradicts what they already built

Phase 1 says "static layouts, mock JSON," with Strapi binding deferred to Week 2. But these students already wrote working Strapi fetch routes in April. Telling them to go back to mock data will read as erasure — frame it as "your API layer is the foundation; now we build the UI on top."

Is there a Strapi instance running?

The plan specifies Strapi v5 on AWS + RDS, but I found no infra config in the repo — no Dockerfile, no App Runner or EC2 definition. If no instance exists yet, Week 2's binding phase has no target and the mock-data approach isn't a choice, it's the only option.

Amplify is still here

amplify/ is live in the repo with uncommitted changes to gddtoolkit2025/cli-inputs.json, while the plan calls for replacing it. Decide the retirement date before students build auth against the wrong system. Unrelated: a 49 MB AWSCLIV2.pkg is committed at the repo root — worth removing sometime, not today.
